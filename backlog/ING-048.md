### [ING-048] Recommender: LLM outfit picker (prompt, call, validation, retry)

**As a** wardrobe owner
**I want** the local text LLM to pick 3 color-coordinated outfits from the candidates
**So that** I get suggestions that read my note and match colors, with no invalid garments

**Acceptance criteria** (Gherkin):
```
Given candidates, weather rules, formality and a note
When the prompt is built
Then each candidate line has exactly id, category, subcategory, dominant_color,
  secondary_colors, pattern, warmth_tier, formality
And no photo path, photo data, or item notes appear anywhere in the prompt
And the prompt includes feels-like, min/max, rain chance, weather code, formality, the note,
  whether outerwear is required/optional/excluded, "temperature unknown" when so,
  and the JSON-only output contract {"outfits":[{"item_ids":[...],"reason":"..."}]}

Given a fake LLM server (httptest)
When the picker calls it
Then it POSTs <LLM_URL>/v1/chat/completions with the configured temperature
And sends "Authorization: Bearer <key>" only when LLM_API_KEY is set
And includes "model" only when LLM_MODEL is non-empty (field absent otherwise)

Given the LLM returns a valid answer
When it is validated
Then 3 outfits are returned in the model's order, each with its item ids and reason

Given an answer that breaks any rule: not exactly 3 outfits; an id not in the candidates;
  missing or duplicate top/bottom/footwear; outerwear missing when required or present when
  excluded; more than one outerwear or headwear; a duplicated id inside an outfit;
  all 3 outfits the same id set; empty reason; unparseable JSON
When it is validated
Then the attempt is invalid

Given the first answer is invalid and the second is valid
When the picker runs
Then exactly 2 LLM calls are made and the second answer is returned

Given both answers are invalid
When the picker runs
Then exactly 2 calls are made and an error marked as an LLM failure is returned

Given the LLM is unreachable (closed server)
When the picker runs
Then exactly 1 call is attempted (no retry) and an LLM-failure error is returned

Given the LLM does not answer within the timeout
When the picker runs
Then it fails with an LLM-failure error; the production timeout is 120 s
  (tests inject a shorter one)

Given the LLM returns a non-2xx status and LLM_MODEL is empty
When the picker runs
Then the error message tells the user to set LLM_MODEL
And with LLM_MODEL set, a non-2xx error does not contain that hint
```
