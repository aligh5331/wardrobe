### [ING-021] Embed the built frontend into the Go binary and serve it

**As a** wardrobe owner
**I want** the built frontend embedded into the Go binary and served alongside
the API
**So that** the whole app runs as one local executable over localhost, as
`07-architecture.md`'s runtime model requires

**Acceptance criteria** (Gherkin):
```
Given frontend/dist has been produced by the frontend build
When the Go binary is built
Then the built assets are embedded with go:embed and served by cmd/server

Given the single binary is running with no separate Node process
When the root URL is opened in a browser
Then the grid UI loads, and requests to /api/... are still routed to the API

Given an unknown path that is not under /api/
When it is requested
Then the SPA entry is served so client-side navigation works, while an unknown
  /api/... path returns 404 rather than HTML

Given a fresh checkout where frontend/dist has not been generated
When go build ./... runs
Then the build still succeeds (a small tracked placeholder keeps the embed
  pattern valid until a real build replaces it)
```

**Spec reference:** `07-architecture.md` "Runtime model" (single Go binary,
`go:embed`, no Wails/Electron, no separate Node process, browser tab at
localhost) and "Frontend" ("Build output: `frontend/dist/`, embedded into the Go
binary at build time")

**Status:** Review

**Depends on:** ING-020 (produces `frontend/dist/`). Also do ING-019 first —
both touch `cmd/server/main.go`.

**Context / implementation notes**
- `frontend/dist/` is gitignored (`.gitignore`), and `go:embed` fails to compile
  when its pattern matches no files, so a fresh clone needs a committed
  placeholder (e.g. `frontend/dist/index.html`) kept tracked via a `.gitignore`
  negation; a real `npm run build` replaces it locally.
- Register the `/api/*` routes before the SPA fallback so the API is never
  shadowed by the HTML handler.
- This completes `07-architecture.md`'s single-binary runtime; before this
  ticket, the grid UI is only reachable through the Vite dev server.

**Out of scope:** any change to the API routes themselves (ING-019) or the UI
(ING-020).

## Implementation notes

**Files**
- `frontend/embed.go` (new) — `package frontend` with the `//go:embed all:dist`
  directive; exports `Dist fs.FS` already `fs.Sub`-rooted at `dist`, so paths
  are `index.html`, `assets/...`.
- `frontend/dist/index.html` (new, tracked) — minimal placeholder: "Frontend not
  built. Run `npm run build` in `frontend/`."
- `internal/api/api.go` (+ `ServeFrontend`, + `contentType`) — the SPA/static
  fallback, registered as Gin's `NoRoute`.
- `cmd/server/main.go` — wires `api.ServeFrontend(router, frontend.Dist)` after
  `api.New`; package doc updated.
- `.gitignore` — `frontend/dist/` → `frontend/dist/*` plus
  `!frontend/dist/index.html` (a negation only works if the parent directory
  itself is not excluded).

**Behavior (maps to the acceptance criteria)**
- **AC1 — embedded and served by cmd/server:** the Go build embeds
  `frontend/dist` via `go:embed`; `cmd/server` passes the resulting FS to
  `api.ServeFrontend`. If the pattern matched no files the build would fail —
  the tracked placeholder guarantees a match.
- **AC2 — single binary, grid UI + API:** `api.New` registers `/api/items` and
  `/api/photos/:filename`; `NoRoute` only fires when no route matched, so API
  requests are never shadowed. `/` and asset paths (`/assets/index-*.js|css`)
  are read from the embedded FS with an extension-based `Content-Type`, so the
  built grid loads with no Node process.
- **AC3 — SPA fallback vs. API 404:** any unmatched path under `/api` or `/api/`
  returns `404` (empty body, never HTML). Every other unmatched path is served
  from `dist`, and if it is not a real file the SPA entry (`index.html`) is
  served so client-side routes work.
- **AC4 — fresh checkout still builds:** the placeholder keeps the embed
  pattern valid before any `npm run build`; `go build ./...` succeeds.

**Assumptions / decisions for Tester + Reviewer**
1. **The embed directive lives in `frontend/embed.go`, not
   `cmd/server/main.go`.** Go's `go:embed` patterns cannot contain `..`, so a
   package at `cmd/server/` cannot embed `../../frontend/dist`. The
   architecture tree's comment ("main.go ... embeds frontend/dist") is
   illustrative; the spec's actual requirements — `go:embed`, build output
   `frontend/dist/`, served by the single `cmd/server` binary — are all met.
   Flagging because it is the one place the implementation has to interpret the
   tree comment. No spec file was changed.
2. **Placeholder content replaced the previously built `index.html`.** The
   working tree had a real (untracked) Vite `index.html`; the tracked file is
   now the minimal placeholder, as the ticket requires. Running
   `npm run build` in `frontend/` regenerates the real entry plus assets for
   AC2 verification; `go build` must then be re-run to re-embed.
3. **Serving is done with `fs.ReadFile` + `c.Data`, not
   `http.FileServer`/`c.FileFromFS`.** `http.FileServer` 301-redirects any path
   ending in `/index.html` to `./`, which would loop against a `NoRoute`
   fallback that rewrites to `index.html`. Reading the embedded file and
   writing it directly is simpler and avoids that redirect; assets are small
   (personal localhost app).
4. **`New`'s signature is unchanged** (`New(st, photosDir)`), so ING-019's
   existing tests still compile and its `Routes()` assertion is untouched. The
   frontend registration is a separate exported function.
5. **`/api` (exact, no trailing slash) is treated as API namespace → 404.**
   The AC says "unknown /api/... path"; treating the bare namespace too keeps
   anything API-shaped out of the HTML fallback.
6. **Traversal safety:** the embedded FS rejects invalid paths (`..`,
   separators), so a crafted non-API path simply misses `fs.ReadFile` and gets
   the SPA entry; it can never read outside the embedded assets.

### Edge cases checked (spec-implied / contract-adjacent)

  of the SPA fallback is the correct reading.
