### [ING-021] Embed the built frontend into the Go binary and serve it

**As a** wardrobe owner
**I want** the built frontend embedded into the Go binary and served alongside
the API
**So that** the whole app runs as one local executable over localhost, as
`07-architecture.md`'s runtime model requires

**Acceptance criteria** (Gherkin):
```
Given frontend/dist has been produced by the frontend build
When the Go binary is built
Then the built assets are embedded with go:embed and served by cmd/server

Given the single binary is running with no separate Node process
When the root URL is opened in a browser
Then the grid UI loads, and requests to /api/... are still routed to the API

Given an unknown path that is not under /api/
When it is requested
Then the SPA entry is served so client-side navigation works, while an unknown
  /api/... path returns 404 rather than HTML

Given a fresh checkout where frontend/dist has not been generated
When go build ./... runs
Then the build still succeeds (a small tracked placeholder keeps the embed
  pattern valid until a real build replaces it)
```

**Spec reference:** `07-architecture.md` "Runtime model" (single Go binary,
`go:embed`, no Wails/Electron, no separate Node process, browser tab at
localhost) and "Frontend" ("Build output: `frontend/dist/`, embedded into the Go
binary at build time")

**Status:** Ready

**Depends on:** ING-020 (produces `frontend/dist/`). Also do ING-019 first —
both touch `cmd/server/main.go`.

**Context / implementation notes**
- `frontend/dist/` is gitignored (`.gitignore`), and `go:embed` fails to compile
  when its pattern matches no files, so a fresh clone needs a committed
  placeholder (e.g. `frontend/dist/index.html`) kept tracked via a `.gitignore`
  negation; a real `npm run build` replaces it locally.
- Register the `/api/*` routes before the SPA fallback so the API is never
  shadowed by the HTML handler.
- This completes `07-architecture.md`'s single-binary runtime; before this
  ticket, the grid UI is only reachable through the Vite dev server.

**Out of scope:** any change to the API routes themselves (ING-019) or the UI
(ING-020).
