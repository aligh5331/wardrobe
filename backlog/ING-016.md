### [ING-016] De-duplicate the acceptance-test module-root helpers and live E2E tests

**As a** wardrobe owner
**I want** the acceptance suite to have one module-root helper, one sample-photo
finder, and one live VLM end-to-end test instead of two near-identical copies
**So that** the suite stops carrying duplicated walkers and hand-copied taxonomy
tables that can drift from `03-taxonomy.md`

**Acceptance criteria** (Gherkin):
```
Given the tests package is compiled both without and with -tags=integration
When it builds
Then exactly one module-root helper exists (repoRoot and moduleRoot collapsed
  into a single shared, non-build-tagged helper)
And it is used by both the integration and non-integration test files

Given the live VLM end-to-end path runs (VLM_URL set, -tags=integration)
When a real garment photo is tagged
Then a single live test asserts all seven tagging fields
  (category, subcategory, dominant_color, secondary_colors, pattern,
  warmth_tier, formality) by validating the response with
  ParseTaggingResult and comparing against the tables read from
  03-taxonomy.md
And no hand-copied taxonomyCategories/taxonomyColors maps remain
And tests/ing_002_live_test.go no longer exists as a separate duplicate
And findSamplePhoto still resolves the sample photo for the surviving test
  (it is moved, not dropped with the deleted file)

Given the suite is run
When go test ./... and go test -tags=integration -run XXX_NONE ./tests/ run
Then the first is green and the second compiles cleanly
```

**Spec reference:** `05-vlm-tagging-spec.md` "Output validation" (the parse +
validate path the live test exercises); `03-taxonomy.md` (the enums the live
test must check against, read from the spec file rather than hand-copied)

**Status:** Ready

**Note:** Acceptance tests are Tester territory (Coder does not write the
acceptance suite), so route this to Tester rather than the usual
Ready→Coder handoff — same pattern as ING-013.

**Context:** Audit finding (duplication / `shrink`): the tests package has two
byte-identical module-root walkers — `repoRoot` (tests/ing_002_client_test.go)
and `moduleRoot` (tests/ing_001_server_integration_test.go) — and two live VLM
E2E tests, `tests/ing_002_live_test.go` and `tests/ing_004_live_test.go`. The
ING-004 live test is a strict superset: it validates every field through
`ParseTaggingResult` and `loadTaxonomy`, while the ING-002 live test checks only
three fields against hand-copied maps. Consolidating to the ING-004 test keeps
the full assertion coverage and removes the drift risk. Do not reduce coverage:
the surviving live test must assert the union of both today.

**Files:** `tests/ing_002_live_test.go` (removed after its helper is moved),
`tests/ing_004_live_test.go`, `tests/ing_002_client_test.go`,
`tests/ing_001_server_integration_test.go`, plus one shared non-tagged helper
location.
