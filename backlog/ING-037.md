### [ING-037] Cross-platform: make the Go suite pass on Windows (line endings, process control, binary names, `photo_path`)

**As a** wardrobe owner
**I want** the acceptance suite to run green on Windows as well as Linux
**So that** platform-dependent test failures stop masking real regressions and the
catalog stores portable photo paths

**Acceptance criteria** (Gherkin):
```
Given the repo is checked out on Windows with core.autocrlf=true
When the tracked text files are read by spec-parsing tests
Then they are LF in the working tree (repo-defined line endings, not machine-defined)

Given the integration-tagged tests are compiled on Windows
When go vet -tags=integration ./tests/ runs
Then the package compiles — no Unix-only syscall usage

Given the process-level harnesses build the real server/CLI binaries
When they execute them on Windows
Then the binaries are executable (named with .exe where required)

Given a photo is persisted through internal/catalog on any OS
When the row is read back
Then photo_path uses the portable forward-slash data/photos/<id><ext> shape

Given the suite is run on Windows
When go test ./..., go test -tags=integration ./tests/, and npm test run
Then all are green
```

**Spec reference:** `07-architecture.md` "Image storage" (files under
`data/photos/`, path in `photo_path`); `04-data-schema.md` `photo_path`; the
integration-tagged suite's process contract. This change makes stored paths and
the test harness match the already-documented `data/photos/<id><ext>` shape on
every OS; it introduces no new enum/schema value and edits no protected file.

**Status:** Done

**Context:** The suite was green on Linux but failed on Windows. Investigation
found four independent, OS-specific causes (none product-logic bugs on Linux):

1. **CRLF line endings.** `git config core.autocrlf=true` on Windows is set and
   the repo had no `.gitattributes`, so tracked text files were checked out as
   CRLF (`git ls-files --eol` → `i/lf w/crlf`). `tests/ing_002_client_test.go`
   compares the prompt parsed out of `05-vlm-tagging-spec.md` verbatim against
   the LF Go literal in `internal/tagging/client.go:32`; the CRLF parse emitted
   `\r\n` and failed `TestING002_AC1_ReturnsRawResponse` (the only
   non-integration failure).
2. **Unix-only syscalls.** `tests/ing_001_server_integration_test.go:71,83` and
   `tests/ing_019_server_integration_test.go:57` used
   `syscall.SysProcAttr{Setpgid: true}` / `syscall.Kill`, which do not exist on
   Windows, so `-tags=integration` failed to build at all on Windows.
3. **Extensionless binaries.** The harnesses built to `…/ingest` and `…/server`
   with `go build -o`; Go writes exactly that name and Windows' exec could not
   launch an extensionless file ("executable file not found in %PATH%").
4. **Platform-dependent `photo_path`.** `internal/catalog/catalog.go` stored
   `filepath.Join(photosDir, …)`, producing `data\photos\<id>.jpg` on Windows vs
   `data/photos/<id>.jpg` on Linux — a portable-data defect, not only a test one.

**What was done**

1. **Line endings (`#1`)**
   - Added `.gitattributes` with `* text=auto eol=lf` (new file, untracked in
     this working tree — Ali must commit it for clones to inherit it).
   - Renormalized the working tree to LF (deleted the tracked files and
     re-checked-out from the index; index blobs were already LF, so this made
     the working tree match the repo). `git ls-files --eol` now reports
     `i/lf w/lf` and `git diff` is empty for those files.
   - Hardened `tests/ing_002_client_test.go`'s `specTaggingPrompt` to normalize
     `\r\n` → `\n` before comparing, so a stale Windows checkout can never make
     the spec prompt differ from the `client.go` literal again.
2. **Process control (`#2`)** — replaced the Unix-only calls with a small
   build-tagged pair of test helpers:
   - `tests/proc_unix_test.go` (`//go:build !windows`): `setProcAttr`
     (`Setpgid`) and `killTree` (`syscall.Kill(-pid, SIGKILL)`).
   - `tests/proc_windows_test.go` (`//go:build windows`): `setProcAttr` is a
     no-op; `killTree` uses `taskkill /F /T /PID` so `go run`'s compiled child
     (not just the `go run` parent) is killed.
   - `startServer`/`killServer` and the ING-019 harness now call
     `setProcAttr(cmd)` / `killTree(cmd)`; the `syscall` import was dropped from
     both integration files.
3. **Binary names (`#3`)** — added `tests/execname_test.go`'s
   `exeSuffix()` (returns `.exe` on Windows, `""` elsewhere) and appended it to
   the three `go build -o` output names (`ing_012_cli_test.go`,
   `ing_018_persist_test.go`, `ing_019_server_integration_test.go`).
4. **Portable `photo_path` (`#4`)** — `internal/catalog/catalog.go` now stores
   `item.PhotoPath = filepath.ToSlash(dest)` (the file I/O still uses the native
   `dest`). Test expectations that compared a created row's `PhotoPath` to a
   native `filepath.Join(...)` were normalized with `filepath.ToSlash(...)`:
   `ing_018_persist_test.go` (×2), `ing_028_catalog_test.go`,
   `ing_032_create_item_test.go`, `ing_032_tester_test.go`,
   `ing_035_create_edit_test.go`, `ing_035_shared_persist_test.go`.
