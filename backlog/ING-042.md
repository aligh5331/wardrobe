### [ING-042] Store: weather location setting (single row, Tehran default, validation)

**As a** wardrobe owner
**I want** my chosen weather location persisted in the local SQLite database
**So that** it survives restarts, and weather always has a location even before I pick one

**Acceptance criteria** (Gherkin):
```
Given a fresh database with no weather location row
When the store reads the weather location
Then it returns the default name "Tehran", country "Iran", latitude 35.69439,
  longitude 51.42151, and no error
And no row is written by the read

Given a valid location {name, country, latitude, longitude}
When the store saves it and then reads the weather location
Then the read returns exactly the saved values

Given a location has already been saved
When a second, different location is saved
Then a read returns the second location and the table holds exactly one row

Given a location with country empty
When it is saved
Then it is accepted (country is optional) and read back with an empty country

Given a location with an empty or whitespace-only name, latitude outside -90..90, or longitude outside -180..180
When the store saves it
Then it returns a validation error whose message names the offending field
  (name, latitude, or longitude), and the previously stored location (or the
  default) is unchanged

Given boundary values latitude -90 / 90 and longitude -180 / 180
When they are saved
Then they are accepted

Given store.Open on an existing Phase 1 database
When it auto-migrates
Then the weather location table is added and existing wardrobe items are untouched
```

**Spec reference:** `04-data-schema.md` "Settings — weather location (Phase 2)"
(single row; fields `name` required, `country` optional, `latitude` -90..90,
`longitude` -180..180; Tehran default when no row); `06-decisions.md`
"Weather location: chosen in the web UI, persisted in SQLite, default Tehran".

**Status:** Ready

**Depends on:** nothing.

**Routing:** Ready → Coder. Touches `internal/store/store.go` (new model in
`AutoMigrate`, get/save methods) plus a test. Validation lives here so the API
(ING-043) maps the named-field error to 400 without a second copy.

**Out of scope:** HTTP routes (ING-043), multiple saved locations, env vars
for location, any change to the `Item` model.
