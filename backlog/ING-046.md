### [ING-046] Config: `LLM_MODEL`, `LLM_TEMPERATURE`; `LLM_URL` required by the server only

**As a** wardrobe owner
**I want** the LLM endpoint settings validated when the server starts
**So that** a misconfigured recommender fails fast, while the ingest CLI keeps working without an LLM

**Acceptance criteria** (Gherkin):
```
Given LLM_TEMPERATURE is unset or empty
When config loads
Then LLMTemperature is 0.4

Given LLM_TEMPERATURE is "0", "0.7", or "1.0"
When config loads
Then it is accepted with that value

Given LLM_TEMPERATURE is non-numeric, NaN, Inf, -Inf, negative, or > 1.0
When config loads
Then it returns an error naming LLM_TEMPERATURE (same rules as VLM_TEMPERATURE)

Given LLM_MODEL is unset/empty or set to "qwen3:8b"
When config loads
Then LLMModel is "" or "qwen3:8b" respectively (trimmed), never an error

Given LLM_URL is empty or whitespace-only
When cmd/server starts
Then it exits with a startup error naming LLM_URL

Given LLM_URL is empty and VLM_URL is set
When cmd/ingest starts
Then it does not fail on LLM_URL (ingest never calls the LLM)

Given LLM_URL is set to a malformed value
When cmd/server starts
Then startup proceeds (no URL-format validation)
```

**Spec reference:** `07-architecture.md` "Env var contract" (`LLM_URL` server
only, `LLM_MODEL`, `LLM_TEMPERATURE`); `06-decisions.md` "LLM config:
`LLM_URL` required by the server only; optional `LLM_MODEL`; fixed 120 s
timeout"; `06-decisions.md` "VLM_TEMPERATURE acceptable range" (rules mirrored).

**Status:** Testing

**Depends on:** nothing.

**Routing:** Ready → Coder. `internal/config/config.go` (new fields, reuse
`floatEnv`), a server-only `LLM_URL` check in `cmd/server/main.go` (or a small
exported config method it calls), tests under `tests/`. Existing
`TestING001_AC5_LLMURLNotValidated` asserts `config.Load` does not reject an
empty `LLM_URL`; that stays true for `Load` itself — keep it passing.

**Out of scope:** calling the LLM (ING-048), serialization/delay options for
the LLM, a configurable timeout.

## Implementation notes

`internal/config/config.go`: `LLMModel` and `LLMTemperature` fields on
`Config`. `Load()` reads `LLM_MODEL` trimmed (same as `VLM_URL`, no
validation) and `LLM_TEMPERATURE` through the existing `floatEnv` helper
with the same `[0, 1]` bounds as `VLM_TEMPERATURE`, default `0.4`. New
method `(*Config) RequireLLMURL()` returns an error naming `LLM_URL` when
`c.LLMURL == ""`, and nil otherwise. `Load()` itself still never rejects
an empty `LLM_URL` — `RequireLLMURL` is the only place that checks it.

`cmd/server/main.go`: one `cfg.RequireLLMURL()` call right after
`config.Load()`, `log.Fatalf` on error. `cmd/ingest` does not call it, so
ingest starts fine with `LLM_URL` empty.

`internal/config/config_test.go`: `setEnv`'s per-test reset list now
includes `LLM_MODEL` and `LLM_TEMPERATURE`, closing a gap where a value
set by one subtest could leak into the next through `t.Setenv`.

`tests/ing_001_config_test.go`: `contractVars` (the shared reset list
`ing_046_llm_config_test.go` also uses) now includes `LLM_MODEL` and
`LLM_TEMPERATURE` for the same reason. `TestING001_AC5_LLMURLNotValidated`
itself is unchanged and still passes: `config.Load()` accepts an empty
`LLM_URL`.

New `tests/ing_046_llm_config_test.go` (package `tests`, black-box against
the exported `config.Load`/`RequireLLMURL` API): default temperature,
accepted values `"0"`/`"0.7"`/`"1.0"`, rejected values (non-numeric, NaN
variants, Inf variants, negative, `>1.0`) each asserting the error names
`LLM_TEMPERATURE`, `LLM_MODEL` unset/empty/set/whitespace-trimmed never
erroring, `RequireLLMURL` on empty/whitespace/tabs-and-newlines naming
`LLM_URL`, `RequireLLMURL` succeeding once `LLM_URL` is set, `Load()`
succeeding with an empty `LLM_URL`, and `RequireLLMURL` accepting a
malformed but non-empty `LLM_URL` unchanged.

New `tests/ing_046_server_integration_test.go` (`//go:build integration`,
run via `go test -tags=integration -run TestING046 ./tests/`): the real
`cmd/server` binary exits 1 with a startup message naming `LLM_URL` for
empty and whitespace-only values, reaches its listen stage with a
malformed but non-empty `LLM_URL`, and the real `cmd/ingest` binary exits
0 with no mention of `LLM_URL` in stderr when `LLM_URL` is empty. Reuses
the existing `startServer`/`killServer`/`assertReachedListenStage`
helpers from the ING-001 integration file and the `newING012Harness`
helper from the ING-012 integration file, both already in this package.
