### [ING-046] Config: `LLM_MODEL`, `LLM_TEMPERATURE`; `LLM_URL` required by the server only

**As a** wardrobe owner
**I want** the LLM endpoint settings validated when the server starts
**So that** a misconfigured recommender fails fast, while the ingest CLI keeps working without an LLM

**Acceptance criteria** (Gherkin):
```
Given LLM_TEMPERATURE is unset or empty
When config loads
Then LLMTemperature is 0.4

Given LLM_TEMPERATURE is "0", "0.7", or "1.0"
When config loads
Then it is accepted with that value

Given LLM_TEMPERATURE is non-numeric, NaN, Inf, -Inf, negative, or > 1.0
When config loads
Then it returns an error naming LLM_TEMPERATURE (same rules as VLM_TEMPERATURE)

Given LLM_MODEL is unset/empty or set to "qwen3:8b"
When config loads
Then LLMModel is "" or "qwen3:8b" respectively (trimmed), never an error

Given LLM_URL is empty or whitespace-only
When cmd/server starts
Then it exits with a startup error naming LLM_URL

Given LLM_URL is empty and VLM_URL is set
When cmd/ingest starts
Then it does not fail on LLM_URL (ingest never calls the LLM)

Given LLM_URL is set to a malformed value
When cmd/server starts
Then startup proceeds (no URL-format validation)
```

**Spec reference:** `07-architecture.md` "Env var contract" (`LLM_URL` server
only, `LLM_MODEL`, `LLM_TEMPERATURE`); `06-decisions.md` "LLM config:
`LLM_URL` required by the server only; optional `LLM_MODEL`; fixed 120 s
timeout"; `06-decisions.md` "VLM_TEMPERATURE acceptable range" (rules mirrored).

**Status:** Done

**Depends on:** nothing.

**Routing:** Ready → Coder. `internal/config/config.go` (new fields, reuse
`floatEnv`), a server-only `LLM_URL` check in `cmd/server/main.go` (or a small
exported config method it calls), tests under `tests/`. Existing
`TestING001_AC5_LLMURLNotValidated` asserts `config.Load` does not reject an
empty `LLM_URL`; that stays true for `Load` itself — keep it passing.

**Out of scope:** calling the LLM (ING-048), serialization/delay options for
the LLM, a configurable timeout.

## Implementation notes

`internal/config/config.go`: `LLMModel` and `LLMTemperature` fields on
`Config`. `Load()` reads `LLM_MODEL` trimmed (same as `VLM_URL`, no
validation) and `LLM_TEMPERATURE` through the existing `floatEnv` helper
with the same `[0, 1]` bounds as `VLM_TEMPERATURE`, default `0.4`. New
method `(*Config) RequireLLMURL()` returns an error naming `LLM_URL` when
`c.LLMURL == ""`, and nil otherwise. `Load()` itself still never rejects
an empty `LLM_URL` — `RequireLLMURL` is the only place that checks it.

`cmd/server/main.go`: one `cfg.RequireLLMURL()` call right after
`config.Load()`, `log.Fatalf` on error. `cmd/ingest` does not call it, so
ingest starts fine with `LLM_URL` empty.

`internal/config/config_test.go`: `setEnv`'s per-test reset list now
includes `LLM_MODEL` and `LLM_TEMPERATURE`, closing a gap where a value
set by one subtest could leak into the next through `t.Setenv`.

`tests/ing_001_config_test.go`: `contractVars` (the shared reset list
`ing_046_llm_config_test.go` also uses) now includes `LLM_MODEL` and
`LLM_TEMPERATURE` for the same reason. `TestING001_AC5_LLMURLNotValidated`
itself is unchanged and still passes: `config.Load()` accepts an empty
`LLM_URL`.

New `tests/ing_046_llm_config_test.go` (package `tests`, black-box against
the exported `config.Load`/`RequireLLMURL` API): default temperature,
accepted values `"0"`/`"0.7"`/`"1.0"`, rejected values (non-numeric, NaN

## Review

**Decision: APPROVED**

Reviewed commit `550f858` plus the uncommitted `tests/ing_046_gaps_test.go`
and the Test results section of this ticket. The review checked the ticket
ACs, `07-architecture.md` "Env var contract", `06-decisions.md` "LLM config"
and "VLM_TEMPERATURE acceptable range", `00-overview.md` hard constraints, and
`AGENTS.md`. Tester's evidence, including the integration run by Ali, is
accepted as recorded. I did not re-run any tests.

- **Spec match.** `Config` gains `LLMModel` and `LLMTemperature`. `Load()`
  trims `LLM_MODEL` with no validation, so the field is empty when unset and
  the request can omit `model` as the spec says. `LLM_TEMPERATURE` goes
  through the existing `floatEnv` with the same `[0, 1]` bounds and `0.4`
  default as `VLM_TEMPERATURE`. Errors name `LLM_TEMPERATURE` because
  `floatEnv` uses the variable name. `Load()` still accepts an empty
  `LLM_URL`, so `TestING001_AC5_LLMURLNotValidated` and `cmd/ingest` are
  unaffected. `RequireLLMURL()` checks only for an empty (already trimmed)
  value, so whitespace-only fails and a malformed URL passes, matching
  `07-architecture.md` ("No URL-format validation; a malformed value
  surfaces as `502` on first recommendation"). `cmd/server/main.go` calls it
  right after `config.Load()` and before the store opens, using the same
  `log.Fatalf("startup: %v", err)` shape as the existing check. `cmd/ingest`
  does not call it.
- **Hard constraints clean.** No network call, no new dependency, no model or
  fine-tuning change, no photo-handling change. The ticket adds no LLM
  client, timeout, serialization option, or recommender code, which keeps to
  the stated out-of-scope list. No secret or `.env` value appears in the diff.
  `git show 550f858 --stat` lists no protected file (`0*.md`, `agents/`,
  `AGENTS.md`) and no `.env`. The only backlog change is this ticket.
- **Over-engineering check: none.** The production diff is two fields, two
  `Load()` blocks, one 3-line method, and one 3-line call in `main.go`. It
  reuses `floatEnv` and the existing `minTemp`/`maxTemp` locals. The method
  sits on `*Config` next to `Warnings()`, so it adds no new pattern.
- **Tests.** The Coder's file maps one test to each AC with black-box calls
  to `config.Load` and `RequireLLMURL`. The integration file uses
  `//go:build integration` like ING-001, ING-008, ING-009, ING-012 and the
  other process-level files, and it reuses the `startServer`,
  `assertReachedListenStage` and `newING012Harness` helpers rather than
  copying them. The unit files carry no tag, like the existing config tests.
  Adding `LLM_MODEL` and `LLM_TEMPERATURE` to `contractVars` and to the
  `setEnv` reset list in `config_test.go` is a two-line change. It stops env
  leaking between subtests, so it stays in scope. Tester's
  `TestING046_Gaps` overlaps little with the Coder's file. The
  whitespace-only `LLM_MODEL` case, `LLM_URL` trimming, and independence of
  the two temperatures are not covered elsewhere. The invalid
  `VLM_TEMPERATURE` subtest re-checks behavior that the ING-008 tests already
  cover, but it is 10 lines and confirms the shared `floatEnv` path still
  names the right variable after the new call was added. Keep all four.
  Nothing is worth deleting.
