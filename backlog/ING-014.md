### [ING-014] Replace hand-rolled `contains` with the stdlib `slices.Contains`

**As a** wardrobe owner
**I want** the local `contains` helper in the tagging validator replaced with
the standard library `slices.Contains`
**So that** the validator stops carrying a hand-rolled utility that the
standard library already ships (and that `validate_test.go` already imports)

**Acceptance criteria** (Gherkin):
```
Given the tagging validator checks a value against an allowed enum list
When that membership check is written
Then it uses slices.Contains, not a locally defined contains loop

Given a valid value, an invalid value, and an empty-string value are
  validated
When ParseTaggingResult runs
Then the accept/reject outcome and the returned *ValidationError
  FailureType/FailureDetail are unchanged from today
And errors.Is(err, ErrInvalidTaggingResult) still holds for every
  rejection

Given the package is built and tested
When go build ./... and go test ./... run
Then both are clean/green
```

**Spec reference:** `05-vlm-tagging-spec.md` "Output validation" (the
malformed-JSON / invalid-enum / missing-required-field rejection reasons the
validator implements); `03-taxonomy.md` (the enum tables it validates against)

**Status:** Ready

**Context:** Audit finding (over-engineering / `stdlib`): `contains()` in
`internal/tagging/validate.go` (lines 186–193) is a hand-rolled
`slices.Contains`. `slices` is already used in `internal/tagging/validate_test.go`,
so no new dependency or import novelty is involved. Pure
behavior-preserving refactor — no enum value, error string, or failure-type
classification may change.

**Files:** `internal/tagging/validate.go` only.
