### [ING-014] Replace hand-rolled `contains` with the stdlib `slices.Contains`

**As a** wardrobe owner
**I want** the local `contains` helper in the tagging validator replaced with
the standard library `slices.Contains`
**So that** the validator stops carrying a hand-rolled utility that the
standard library already ships (and that `validate_test.go` already imports)

**Acceptance criteria** (Gherkin):
```
Given the tagging validator performs its enum membership checks
When the refactor is complete
Then internal/tagging/validate.go calls slices.Contains and defines no
  local contains helper, confirmed by reviewing the diff — not by a
  new test

Given the existing suite is run
When go build ./..., go vet ./..., and go test ./... run
Then all three are clean/green
And no new test file or test function is added for this refactor, and no
  existing test file is modified
```

No new coverage is added: `internal/tagging/validate_test.go` and
`tests/ing_004_validate_test.go` already assert accept/reject behavior and
the exact `*ValidationError` `FailureType`/`FailureDetail` values. A pure

malformed-JSON / invalid-enum / missing-required-field rejection reasons the
validator implements); `03-taxonomy.md` (the enum tables it validates against)
