### [ING-038] `internal/logging`: configured `log/slog` logger (stderr + `logs/app.log`)

**As a** wardrobe owner
**I want** one `log/slog` logger built from the validated level/format that
writes to stderr and an append-only `logs/app.log`
**So that** every runtime log record shares the same sinks, level, and format,
and the whole app still ships with no logging dependency

**Acceptance criteria** (Gherkin):
```
Given a validated LOG_LEVEL and LOG_FORMAT
When a logger is built from them
Then records at or above the level are emitted to both the stderr sink and
  logs/app.log
And records below the level are emitted to neither

Given LOG_LEVEL=warn
When a debug and an info record are logged followed by a warn record
Then only the warn record appears in the sinks

Given LOG_FORMAT=json
When a record is logged
Then each sink line is a parseable JSON object carrying the record's
  level, message, and attributes

Given LOG_FORMAT=text
When a record is logged
Then each sink line is the text handler's key=value rendering (not JSON)

Given logs/app.log does not exist
When the logger is built
Then the file is created and the first records are appended to it
And a second build appends to the same file rather than truncating it

Given the log path and the writer are injectable
When a unit test builds a logger pointed at a temp directory and a bytes.Buffer
Then no test writes to the repository's real logs/ directory or real stderr

Given logs/app.log cannot be opened (unwritable path or a directory)
When the logger is built
Then building does not fail
And a warning record naming the failure and the fallback to stderr only is
  emitted to the stderr sink
And subsequent records still reach stderr

Given the ING-005 attempt trail logs/vlm-attempts.jsonl
When the logger is built
Then that trail is separate and unchanged — its records are not merged into
  logs/app.log
```

**Spec reference:** `07-architecture.md` "## Logging" — "Sinks: process stderr
and `logs/app.log` (append/create), both gitignored", "Level and format:
`LOG_LEVEL` sets the minimum level; `LOG_FORMAT` selects a text handler … or a
JSON handler. Both apply to stderr and `logs/app.log` alike", "Failure to open
`logs/app.log`: startup logs a warning and continues with stderr only; it is not
a hard error", and "`logs/vlm-attempts.jsonl` (ING-005) is a separate,
structured attempt trail and is unchanged"; the `LOG_LEVEL`/`LOG_FORMAT` rows of
`07-architecture.md` "### Env var contract"; `06-decisions.md` "Structured
logging: stdlib `log/slog`, local stderr + file, env-configurable
level/format" (stdlib only, sinks, robustness).

**Status:** Ready

**Context:** New package `internal/logging`. It consumes the already-validated
`Config.LogLevel`/`Config.LogFormat` from ING-037 — it does not re-validate env
vars. `io.MultiWriter` over the stderr writer and the open file is the
`07-architecture.md` sink contract; the exact constructor/option names are a
Coder choice, but the injectable path and writer are required so unit tests
never touch the real `logs/`. No third-party logging dependency: `go.mod` must
stay unchanged (stdlib `log/slog` only).

**Routing:** Ready → Coder. Touches `internal/logging/` (new) and its tests.

**Depends on:** ING-037 (the validated `LogLevel`/`LogFormat` fields). Do not
start this ticket first if ING-037 is not yet Done.

**Out of scope:** the Gin access-log middleware (ING-039); migrating
`cmd/ingest`/`cmd/server` off stdlib `log` and wiring the logger into startup
(ING-040); any change to `logs/vlm-attempts.jsonl` (ING-005).

**Test note:** package-local unit tests are sufficient (temp dir + injected
buffer). Cover both formats, level filtering, append (not truncate) across two
builds, the open-failure fallback warning, and — as the key non-regression — that
the injected path means nothing under the repo's `logs/` is touched. No `0*.md`,
`agents/*.md`, or `AGENTS.md` edits; `go.mod`/`go.sum` unchanged.
