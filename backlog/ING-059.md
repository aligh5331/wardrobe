### [ING-059] Recommender eval: trap wardrobe, live run, human-rated Markdown form, summary

**As a** wardrobe owner
**I want** an opt-in eval that runs the real recommender against my configured LLM
on a fixed trap wardrobe and writes a Markdown form I rate by hand
**So that** I have a baseline for today's prompt and can tell whether a prompt
change (ING-060) actually gives better outfits

**Acceptance criteria** (Gherkin):

## Implementation notes

Done in one pass, in this session at Ali's request. Test code only; nothing under
`cmd/` or `internal/` changed, and `go.mod`/`go.sum` are unchanged.

- `tests/recommend_eval_helpers_test.go` (untagged) has the trap wardrobe (35 rows,
  ids from `evalID(n)`), the 4 scenarios, `outfitFlags`/`repeatFlag`, the form
  writer `writeEvalForm`, the parser `parseEvalForm` and `summaryRow`.
- `tests/recommend_eval_test.go` (`//go:build integration`) has `TestRecommendEval`
  and `TestRecommendEvalSummary`. The live run goes through `recordingProxy`, an
  httptest handler that forwards each request unchanged to `LLM_URL` and keeps
  the request bodies per `Pick` call. That gives the fingerprint and first-try
  validity (one request = valid on the first try).
- `tests/ing_059_eval_test.go`: 8 unit tests covering taxonomy validity, the
  scenario rules and slots, every auto-flag (firing and not firing), repeat,
  label sanitizing, the form round trip and summary row, malformed ratings and
  form-name matching.
- `tests/evals/recommender/README.md`: how to run, fill and summarize.

**Assumptions**

- The form's weather line labels only the WMO codes the scenarios use (0, 1, 2,
  3, 61). The full production table is ING-060's job.
- "Its note" is printed as `Request note: ...`, so it can't be confused with an
  outfit's `- Note:` rating field.
- A run whose 3 outfits share a top or bottom gets a `Run auto-flag: repeat`
  line under the rated run, besides its count in the table.
- `config.Load()` still needs `VLM_URL`, as the server does. With `LLM_URL` set
  and `VLM_URL` missing, the eval fails with the config error instead of
  skipping.
- If two forms share a minute and a label, the later run overwrites the earlier
  form.

**Verification**

- `gofmt -l` clean; `go vet ./...` and `go vet -tags=integration ./tests/`
  clean; `go test ./...` passes.
- Skip path: with `LLM_URL` unset, `TestRecommendEval` is SKIP and makes no call.
- End to end against a local fake OpenAI-compatible server (scratch script, not
  committed). It returned valid outfits and one deliberately invalid reply:
  - 12/12 valid runs; cold-rain showed first-try 2/3, so the retry was detected.
  - `repeat` = 3 per scenario, which is correct, since the fake reused one bottom.
  - The form contained neither the API key nor the URL.
  - With one score, one would-wear and one variety filled in, the summary
    printed `rated=1/12 | avg score=5.00 | would wear=100% | avg variety=2.00`.
  - With `Score (1-5): 9` it failed with `line 35: Score must be 1-5 or _`.
  - The smoke-test form was deleted afterwards.
