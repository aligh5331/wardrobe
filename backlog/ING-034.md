### [ING-034] Frontend: add a garment (upload → local draft → correct → save)

**As a** wardrobe owner
**I want** to upload one garment photo in the browser, see the local VLM's draft,
correct it, and save it
**So that** I can catalog a garment without the CLI and confirm the tags before
they are written

**Acceptance criteria** (Gherkin):
```
Given the catalog UI
When the user activates an add control
Then a form with a file input appears, accepting .jpg / .jpeg / .png / .webp

Given a chosen photo file
When the user submits it
Then the client POSTs multipart to /api/items/photo and shows a loading state
  while the local VLM tags it

Given the upload succeeds
When the draft returns
Then its seven tagging fields pre-fill editable inputs (plus optional notes)
  with a preview of the uploaded photo, and nothing is persisted yet

Given the draft form
When it needs the valid values for a field
Then it loads them from GET /api/taxonomy (ING-036) rather than a bundled
  client-side copy, so the choices match the enums the server validates against

Given the draft is shown
When the user corrects fields and saves
Then the client POSTs /api/items with the item id and the corrected fields, and
  on a 2xx the grid refreshes and shows the new item

Given tagging fails after the retry-once policy
When the error returns
Then the UI surfaces it and lets the user retry or pick another photo, with
  nothing persisted

Given the server returns 400 naming a field
When the user saves
Then the named field is surfaced to the user and the error is not silently
  swallowed

Given the change
When it is reviewed against the project's constraints
Then it uses only the local API, adds no runtime dependency, and is covered by
  Vitest + Testing Library tests under frontend/ (npm test)
```

**Spec reference:** `07-architecture.md` "Backend" → "Catalog write API

  optional, per `04-data-schema.md`.

  No new dependency introduced.

  response rather than re-`GET /api/items`.
- The empty-catalog copy ("Run the ingestion pipeline to add garments") was
  left untouched to avoid scope creep; the Add control is now in the header
  regardless of catalog state.
