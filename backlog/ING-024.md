### [ING-024] Set up the frontend test runner: Vitest + Testing Library

**As a** wardrobe owner
**I want** `frontend/` to have a working React DOM test setup — `vitest` +
`jsdom` + `@testing-library/react` + `@testing-library/jest-dom` — and the
ING-020 grid behavior captured as real component tests
**So that** future UI tickets assert rendered behavior instead of grepping
source strings and built-bundle text (the gap recorded in `06-decisions.md`
"Testing tooling")

**Acceptance criteria** (Gherkin):
```
Given the frontend toolchain is set up
When `npm test` runs in frontend/
Then Vitest executes in a jsdom environment and the suite is green

Given the ING-020 grid page behavior
When the component tests render <App /> with a stubbed fetch
Then they assert, by querying the rendered DOM:
  - one card per returned item, each showing its photo_url and its tagged
    fields
  - the empty-catalog state when the API returns []
  - that a failed/absent photo still leaves the item's fields rendered and
    shows a missing-photo placeholder instead of breaking the page

Given the new dependencies
When the diff is reviewed
Then vitest, jsdom, @testing-library/react and @testing-library/jest-dom are
  frontend/ devDependencies only (no runtime dependency), and `npm run build`
  still produces frontend/dist/ with the same Tailwind v4 output

Given the existing suites
When `go test ./...` and `npm run build` run
Then both stay green and no Go source is changed

Given the tooling setup
When the diff is reviewed
Then `vite.config.js` carries the Vitest config (jsdom environment +
  setup file) and `package.json` has a `test` script; test files live under
  `frontend/` per the decision, not under tests/
```

**Spec reference:** `06-decisions.md` "Testing tooling: Vitest + Testing
Library for the frontend, stdlib-first for Go"; `07-architecture.md`
"Frontend" (React + Vite SPA, Tailwind v4); `backlog/ING-020.md` AC1–AC3 (the
rendered behavior being ported)

**Status:** Ready

**Context / routing:** `agents/tester.md`'s permission block denies `src/**`,
so component tests co-located under `frontend/` cannot be authored by Tester —
they are written by Coder as part of this tooling setup, and Tester verifies
this ticket normally. Per the decision, tests live under `frontend/` (e.g.
co-located `*.test.jsx`) and run via `npm test`; this deliberately does not use
the Go `tests/` layout. Stub `fetch` with Vitest's built-in
`vi.stubGlobal('fetch', …)` rather than adding a mock-server dependency.
`@testing-library/user-event` is **not** added — there is no interaction UI yet
(the decision defers it until the edit/re-tag UI exists).

**Do not delete `tests/frontend/ing_020_app_test.mjs` here** — it is retired by
ING-025 once this suite covers the same branches.

**Out of scope:** any change to `App.jsx`/UI behavior (ING-020), the API, or
the Go tooling; MSW, Playwright/Cypress, Storybook (see the decision's rejected
alternatives).

**Note:** `npm` commands are not in Coder's explicit bash allowlist and will
prompt for approval — expected, same as ING-020's `npm install`/`npm run build`.
