### [ING-024] Set up the frontend test runner: Vitest + Testing Library

`jsdom` + `@testing-library/react` + `@testing-library/jest-dom` — and the

**So that** future UI tickets assert rendered behavior instead of grepping

"Testing tooling")

  Run the ingestion pipeline to add garments." text is found, no cards are
  rendered, and the error text is absent.
- **AC3 — failed/absent photo.** Two tests: one fires `fireEvent.error()` on
  the rendered `<img>`; one passes `photo_url: ''`. Both assert the
  `role="img"` / `aria-label="Missing photo"` placeholder appears, the card's
  field text is still present, and the original photo is gone (failed case).
  Neither can unmount the page.
- **AC4 — deps are dev-only + build unchanged.** All four are under
  `devDependencies`; `npm run build` reproduces the same content-hashed
  Tailwind v4 output (see verification below). No Go source changed.

**Assumptions / decisions for Tester + Reviewer**
1. **`"test": "vitest run"`, not watch mode.** `npm test` must be
   non-interactive and exit with the suite result, so CI-style `run` is used.
2. **Explicit imports; no `globals: true`.** The tests import
   `describe/it/expect/vi` from `vitest` and `render/screen/fireEvent/within/
   cleanup` from `@testing-library/react`. `afterEach` calls `cleanup()` and
   `vi.unstubAllGlobals()`. This avoids relying on injected globals and keeps
   each test file self-contained.
3. **No `@testing-library/user-event`**, per the ticket — there is no
   interaction UI; a failed image is simulated with `fireEvent.error`, which is
   exactly the DOM event `App.jsx`'s `onError` handles.
4. **`@testing-library/dom` is not in `package.json`.** It is a peer dependency
   of `@testing-library/react` v16; npm resolves it into `node_modules`
   automatically. The ticket lists the four explicit deps and none of them is
   runtime, which is what the AC asks for.
5. **No change to `App.jsx`.** All three ING-020 branches are already
   DOM-testable as written; `ItemCard` stays module-private and is exercised
   through `<App />`, as the AC specifies.
6. **`tests/frontend/ing_020_app_test.mjs` left untouched** (retired by
   ING-025, per the ticket).
7. **Skills check:** reviewed the available skills before coding. The only
   frontend-related one, `tailwind-v4-shadcn`, covers shadcn/theme setup that
   this ticket explicitly does not use; no skill exists for Vitest/Testing
   Library. Nothing from it was applied.
