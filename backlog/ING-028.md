### [ING-028] Known issue: ingest `persist` has no rollback/cleanup on partial failure

**As a** wardrobe owner
**I want** a failed ingest persist to leave no half-written state (an orphan
photo with no catalog row, or a row pointing at a missing photo)
**So that** `data/photos/` and `data/wardrobe.db` cannot silently drift apart

**Known issue (current behavior):** `cmd/ingest/main.go`'s `persist` copies the
photo into `data/photos/<item_id>.<ext>` and then calls `st.Insert`. If the
copy succeeds and the insert fails, the copied photo is left behind as an
orphan; the process exits nonzero and the catalog has no record of it. The
function's own comment says "retry/rollback/cleanup is deliberately out of
scope for this sprint." Observed while surveying the Phase 1 pipeline; not a
failure of any merged ticket.

**Draft acceptance criteria (do not treat as Ready — behavior is undecided):**
```
Given persist has copied the photo into data/photos/<item_id>.<ext>
When the catalog insert fails
Then <behavior to be decided> — no orphan photo remains, or the failure is
  explicitly recoverable by re-running

Given the photo copy fails
When the ingest process continues
Then no catalog row is inserted for that item
```

**What is missing for Ready** (Planner cannot choose this):
- An approved decision on the desired failure behavior: delete the copied
  photo, make ingest idempotent/re-runnable, or leave the orphan for manual
  recovery. Each has different scope.
- Confirmation that this is in Phase 1 scope now rather than next-sprint
  hardening once the pipeline has been used on the real wardrobe.

Until then this ticket stays at **Backlog** — it is logged so the issue is not
lost, not cleared for Coder.

**Spec reference (for context only — no approved spec defines this behavior
yet):** `05-vlm-tagging-spec.md` "Acceptance criteria (for the first ingestion
ticket)" ("the record is written to the catalog store");
`06-decisions.md` "Ingest→DB wiring: direct call, no provider/service
abstraction yet"; `07-architecture.md` "Backend" (`data/wardrobe.db`,
`data/photos/`); superseded-scope comment in `cmd/ingest/main.go:persist`.

**Status:** Backlog

**Out of scope:** any implementation until the behavior decision above lands;
