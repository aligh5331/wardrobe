### [ING-001] Load and validate VLM/LLM env var contract at startup

**As a** wardrobe owner
**I want** the server to load and validate `VLM_URL`, `VLM_API_KEY`,
`VLM_SERIALIZE_REQUESTS`, and `VLM_REQUEST_DELAY_MS` at startup
**So that** misconfiguration fails fast and loudly instead of causing
confusing errors mid-ingestion

**Acceptance criteria** (Gherkin):
```
Given VLM_URL is unset or empty
When the server starts
Then it exits with a startup error naming VLM_URL as the missing
  required variable

Given VLM_API_KEY is unset
When the server starts
Then startup proceeds normally and no Authorization header is sent on
  VLM requests

Given VLM_REQUEST_DELAY_MS is set to a nonzero value and
  VLM_SERIALIZE_REQUESTS is false or unset
When the server starts
Then it logs a startup warning that the delay will not be applied, and
  proceeds without a hard error

Given VLM_SERIALIZE_REQUESTS is unset
When the server starts
Then it defaults to false (concurrent VLM requests, no artificial
  bottleneck)

Given LLM_URL is unset
When the server starts
Then startup proceeds normally — LLM_URL validation is NOT enforced in
  Phase 1, since there is no Phase 1 consumer of it yet
```

**Spec reference:** `07-architecture.md` "Env var contract" and "VLM
request behavior" sections; `06-decisions.md` "VLM request concurrency"
and "`LLM_URL`/`LLM_API_KEY` provisioned ahead of use" entries
