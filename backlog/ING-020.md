### [ING-020] Frontend grid UI: read-only browse of catalog items

**As a** wardrobe owner
**I want** a React/Vite/Tailwind v4 page that lists cataloged items as a grid
with their photos and tagged fields
**So that** I can actually browse what the ingestion pipeline has cataloged

**Acceptance criteria** (Gherkin):
```
Given the frontend runs with the ING-019 API reachable
When the grid page loads
Then it fetches GET /api/items and renders one card per item showing the item's
  photo (via photo_url) and its tagged fields

Given the catalog is empty (API returns [])
When the grid page loads
Then it renders an empty state and no error

Given an item whose photo fails to load
When the grid renders
Then the card still shows the item's fields and a missing-photo placeholder
  instead of breaking the page

Given the toolchain is set up
When npm run build runs
Then it produces frontend/dist/ using Tailwind v4 as described in
  07-architecture.md — the @tailwindcss/vite plugin, a single
  @import "tailwindcss" entry point, and no tailwind.config.js
```

**Spec reference:** `07-architecture.md` "Frontend" (React + Vite SPA, Tailwind
v4 specifics, build output `frontend/dist/`) and "Runtime model"; the
ING-019 "Agreed read-only contract" for `GET /api/items` and
`GET /api/photos/<file>`

**Status:** Review

**Depends on:** ING-019 (the API contract). Do not start until ING-019 is Done.

**Context / implementation notes**
- Read-only browse only — no edit, delete, re-tag, or manual-correction controls.
  Manual correction is a likely Sprint 3+ need, not this sprint's work.
- For local development, point the Vite dev server at the Go API via a proxy
  rather than adding CORS to the backend; in the built/embedded app the UI and
  API are same-origin (ING-021).
- Use `photo_url` from the API for images; do not reconstruct filesystem paths in
  the browser.
- `07-architecture.md` warns against v3-era Tailwind scaffolding: no
  `tailwind.config.js`, no separate PostCSS/autoprefixer config, no
  `@tailwind base/components/utilities` directives. The repo skill
  `tailwind-v4-shadcn` covers Tailwind v4 + Vite setup if a component library is
  wanted; shadcn is optional and not required by the architecture.

**Out of scope (per Sprint 2 scope):** any write/edit/manual-correction UI,
flagged-item review UI, and pagination/filtering design.

## Implementation notes

**Files added** (all new; `frontend/` previously held only `src/.gitkeep`)
- `frontend/package.json` — Vite scripts (`dev`/`build`/`preview`) and deps:
  React 19, Vite 7, `@vitejs/plugin-react`, `tailwindcss` v4,
  `@tailwindcss/vite`.
- `frontend/vite.config.js` — `plugins: [react(), tailwindcss()]`; dev-only
  `server.proxy` sends `/api` to `http://localhost:8080` so the dev server can
  reach the Go API without CORS.
- `frontend/index.html` — Vite entry, mounts `#root`, loads
  `/src/main.jsx`.
- `frontend/src/index.css` — the single entry point, exactly
  `@import "tailwindcss";`.
- `frontend/src/main.jsx` — React root render.
- `frontend/src/App.jsx` — the grid page.
- `frontend/package-lock.json` — resolved install (generated).

**Behavior (maps to the acceptance criteria)**
- **Grid fetch/render** — `App` fetches relative `/api/items` on mount. A
  `200` JSON array becomes `items`; `Array.isArray` guards a non-array body.
  Each item renders an `ItemCard` `<li>` with the photo via `item.photo_url`
  (no path reconstruction) plus the tagged fields: category, subcategory,
  dominant_color, secondary_colors (joined), pattern, warmth_tier, formality,
  added_date, notes.
- **Empty catalog** — `items.length === 0` after a successful fetch renders a
  plain "No items cataloged yet." message; no error state is entered.
- **Broken photo** — the `<img>` has `onError={() => setPhotoFailed(true)}`;
  on failure the card swaps to a `role="img"` "No photo" placeholder while the
  field `<dl>` still renders. An item with an empty `photo_url` also gets the
  placeholder. The failure cannot unmount the page.
- **Fetch error** — a non-OK response or network failure shows a single
  "Could not load the catalog." line; it does not throw during render.
- **Tailwind v4 build** — `npm run build` runs `vite build`; the
  `@tailwindcss/vite` plugin compiles the `@import "tailwindcss"` entry into
  `frontend/dist/`. There is **no** `tailwind.config.js` and **no**
  `postcss.config.js` anywhere under `frontend/`.

**Assumptions / decisions for Tester + Reviewer**
1. **Plain JavaScript (`.jsx`), not TypeScript.** The architecture fixes
   React + Vite + Tailwind v4 but does not mandate TS; the skill's TS/shadcn
   template is optional. JSX keeps the build to a single `vite build` step
   (no `tsc` type-check gate) and avoids extra config files. If a future
   ticket wants TS, that is a separate change, not an ING-020 defect.
2. **No shadcn/ui or component library.** The ticket says shadcn "is optional
   and not required by the architecture." Plain Tailwind utility classes are
   used, so no `components.json`/`clsx`/`tailwind-merge`/radix deps were
   added.
3. **No dark mode / theme provider.** Not in the ticket; the four-step
   `@theme inline` shadcn pattern is for component-library theming, which is
   not used here. A single `@import "tailwindcss";` is exactly what AC4 asks
   for.
4. **Relative `/api/items` fetch, proxy only in dev.** This satisfies "point
   the Vite dev server at the Go API via a proxy rather than adding CORS" and
   keeps the built app same-origin for ING-021. No API base URL / env var was
   introduced.
5. **Error state added beyond the three listed cases.** A real fetch/HTTP
   failure would otherwise render as an empty catalog; a one-line error is
   cheaper than a misleading empty state. It is not a fetch of a new endpoint
   or a write path.
6. **Lockfile committed.** `package-lock.json` is tracked so Tester and later
   builds resolve the same versions; `node_modules/` and `dist/` remain
   gitignored (root `.gitignore`).

**No spec contract touched** — no change to `0*.md`, `agents/*.md`,
`AGENTS.md`, the API, or any taxonomy/schema/enum value; no new env var; no
cloud/hosted dependency (React/Vite/Tailwind are build-time local tooling).

### Edge cases checked (spec-implied / contract-adjacent)

- **Non-array 2xx body → empty state, not crash** — `Array.isArray` guard;
  the agreed ING-019 contract returns an array, but this keeps a stray
  200-`{}` from throwing in `items.map`.
- **Empty/absent `photo_url` → placeholder** — `Boolean(item.photo_url)`; the
  same path as a failed load.
- **`secondary_colors` null/empty → no crash** — `(item.secondary_colors ?? []).join(', ')`,
  consistent with the schema's "0 or more" list; the empty value is simply omitted
  from the field list.
- **Error path distinct from empty** — `status === 'error'` is only set in
  `.catch`, so a network/HTTP failure shows one error line rather than a
  misleading empty catalog (Coder assumption #5).
- **Read-only surface** — test asserts `App.jsx` contains no `method:`,
  `POST`/`PUT`/`DELETE`/`PATCH`, `<button`, `<form`, or `onClick`; only
  `GET /api/items` is issued, matching the ticket's "read-only browse only" and
  the sprint's no-write-route constraint.
- **Same-origin/proxy** — the fetch is relative and the dev proxy targets
  `localhost:8080`; no CORS was added to the backend and no API base URL/env
  var was introduced, matching the ticket's dev-proxy note.
- **React StrictMode double-fetch** — `useEffect`'s `cancelled` guard prevents
  a stale response from updating state after cleanup.
