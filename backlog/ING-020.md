### [ING-020] Frontend grid UI: read-only browse of catalog items

**As a** wardrobe owner
**I want** a React/Vite/Tailwind v4 page that lists cataloged items as a grid
with their photos and tagged fields
**So that** I can actually browse what the ingestion pipeline has cataloged

**Acceptance criteria** (Gherkin):
```
Given the frontend runs with the ING-019 API reachable
When the grid page loads
Then it fetches GET /api/items and renders one card per item showing the item's
  photo (via photo_url) and its tagged fields

Given the catalog is empty (API returns [])
When the grid page loads
Then it renders an empty state and no error

Given an item whose photo fails to load
When the grid renders
Then the card still shows the item's fields and a missing-photo placeholder
  instead of breaking the page

Given the toolchain is set up
When npm run build runs
Then it produces frontend/dist/ using Tailwind v4 as described in
  07-architecture.md — the @tailwindcss/vite plugin, a single
  @import "tailwindcss" entry point, and no tailwind.config.js
```

**Spec reference:** `07-architecture.md` "Frontend" (React + Vite SPA, Tailwind
v4 specifics, build output `frontend/dist/`) and "Runtime model"; the
ING-019 "Agreed read-only contract" for `GET /api/items` and
`GET /api/photos/<file>`

**Status:** Ready

**Depends on:** ING-019 (the API contract). Do not start until ING-019 is Done.

**Context / implementation notes**
- Read-only browse only — no edit, delete, re-tag, or manual-correction controls.
  Manual correction is a likely Sprint 3+ need, not this sprint's work.
- For local development, point the Vite dev server at the Go API via a proxy
  rather than adding CORS to the backend; in the built/embedded app the UI and
  API are same-origin (ING-021).
- Use `photo_url` from the API for images; do not reconstruct filesystem paths in
  the browser.
- `07-architecture.md` warns against v3-era Tailwind scaffolding: no
  `tailwind.config.js`, no separate PostCSS/autoprefixer config, no
  `@tailwind base/components/utilities` directives. The repo skill
  `tailwind-v4-shadcn` covers Tailwind v4 + Vite setup if a component library is
  wanted; shadcn is optional and not required by the architecture.

**Out of scope (per Sprint 2 scope):** any write/edit/manual-correction UI,
flagged-item review UI, and pagination/filtering design.
