### [ING-011] A malformed VLM_URL surfaces as ErrVLMUnreachable on use

**As a** wardrobe owner
**I want** a malformed `VLM_URL` to fail at request time as the ING-002
`ErrVLMUnreachable`, with no new startup validation
**So that** a bad URL has one distinct, actionable failure mode that
callers already handle, rather than a differently-classified plain error

**Acceptance criteria** (Gherkin):
```
Given VLM_URL is malformed or not a usable URL (e.g. "not a url", a bare
  hostname "vlm.local", or "http://")
When Tag is called
Then the returned error satisfies
  errors.Is(err, tagging.ErrVLMUnreachable)

Given VLM_URL is well-formed but the host is unreachable
When Tag is called
Then the error is still ErrVLMUnreachable (ING-002 behavior unchanged)

Given VLM_URL is empty or unset
When the server starts
Then it still exits with the startup error naming VLM_URL (ING-001
  behavior unchanged — this ticket adds no startup URL validation)
```

**Spec reference:** `07-architecture.md` "Env var contract" (`VLM_URL`
row); `06-decisions.md` "Env var bounds" entry

**Prerequisite:** the `07-architecture.md` / `06-decisions.md` update
stating malformed-URL behavior must land before Coder starts.

**Status:** Ready

**Decision:** Ali, settling ING-009 decision 1 — a malformed `VLM_URL` is
accepted at startup and surfaces later as an "unreachable" error.
Follow-up from the ING-009 audit, same pattern as ING-006 → ING-008.
