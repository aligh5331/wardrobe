### [ING-044] Frontend: weather panel (current + today, WMO code label)

**As a** wardrobe owner
**I want** a small weather panel in the web UI
**So that** I see today's weather for my location next to my wardrobe

**Acceptance criteria** (Gherkin):
```
Given GET /api/weather returns 200
When the app loads
Then a weather panel shows the location name, current temperature, apparent
  temperature, condition, today's min/max temperature, and today's
  precipitation chance

Given a weather_code in the response
When the panel renders the condition
Then the label comes from a frontend-only WMO code → label map (the backend
  sends only the raw code)

Given a weather_code not in the map
When the panel renders
Then it still renders the other values without crashing

Given GET /api/weather returns 502 (or the request fails)
When the app loads
Then the panel shows a weather error message, and the catalog grid and
  "Add garment" flow load and work unchanged

Given the frontend code
When it is inspected
Then it calls only localhost /api/weather (no Open-Meteo origin in the bundle)
```

**Spec reference:** `07-architecture.md` "Backend" → "Weather (Phase 2)" (UI
paragraph: panel fields; "`weather_code` is the raw WMO code; mapping it to a
label/icon is a frontend concern"; weather failures never affect catalog);
`06-decisions.md` "Weather provider: Open-Meteo, backend-proxied, no API key"
(browser only talks to localhost).

**Status:** Ready

**Depends on:** ING-043 (`GET /api/weather`).

**Routing:** Ready → Coder. New component under `frontend/src/` rendered from
`App.jsx`, Tailwind v4 classes, one vitest test file mocking `fetch`.

**Out of scope:** change-location search (ING-045), icons, multi-day forecast,
any outfit suggestion.
