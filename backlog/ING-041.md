### [ING-041] Weather: `internal/weather` Open-Meteo client (forecast + geocoding search)

**As a** wardrobe owner
**I want** a backend client that fetches today's weather and searches cities from Open-Meteo
**So that** the API can serve weather for my saved location without the browser ever calling a third party

**Acceptance criteria** (Gherkin):
```
Given a latitude/longitude and a fake Open-Meteo forecast server (httptest)
When the client fetches the forecast
Then it sends exactly one GET to the forecast endpoint with latitude, longitude,
  current=temperature_2m,apparent_temperature,weather_code,precipitation,
  daily=temperature_2m_min,temperature_2m_max,precipitation_probability_max,weather_code,
  timezone=auto and forecast_days=1
And it returns current {temperature_c, apparent_temperature_c, weather_code,
  precipitation_mm} and today {temperature_min_c, temperature_max_c,
  precipitation_probability_max, weather_code} mapped 1:1 from the response
  (daily values taken from index 0), weather_code as the raw WMO integer

Given a search text and a fake geocoding server returning results
When the client searches cities
Then it calls the geocoding search endpoint with that text and a count of 10
And it returns at most 10 results, each {name, country, admin1, latitude, longitude}

Given the fake geocoding server returns zero results (no "results" key, or an empty list)
When the client searches cities
Then it returns an empty, non-nil list and no error

Given the fake server is unreachable (closed), returns a non-2xx status, or returns an unparseable body
When either call (forecast or search) is made
Then it returns an error (no panic, no partial result) that callers can identify
  as an upstream weather failure (errors.Is on an exported sentinel), and the
  error message distinguishes unreachable/timeout vs non-2xx status vs unparseable body

Given a fake server that does not answer within the timeout
When either call is made
Then the call fails with the upstream error after the client's outbound timeout;
  the production timeout is 10 s (tests may inject a shorter one)

Given the package tests
When they run
Then all HTTP goes to httptest servers via injectable base URLs; no test touches the real network
```

**Spec reference:** `07-architecture.md` "Backend" → "Weather (Phase 2)" (exact

city result shape, up to 10 results, 10 s outbound timeout);
