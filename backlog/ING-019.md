### [ING-019] First Gin routes: read-only catalog list + photo serving

**As a** wardrobe owner
**I want** `cmd/server` to serve a read-only JSON list of catalog items and the
stored photos over Gin, on a configurable listen address
**So that** the grid UI has an API to read from, and ING-001's standing Review
condition (real Gin, configurable address, no placeholder mux) is discharged

**Acceptance criteria** (Gherkin):
```
Given cmd/server starts with the env contract satisfied and no address override
When it listens
Then it serves through Gin (the stdlib http.NewServeMux placeholder in
  cmd/server/main.go is gone) on the default :8080

Given an address override is supplied on the command line
When cmd/server starts
Then it binds that address instead of :8080

Given catalog rows exist
When a client GETs /api/items
Then it receives 200 with a JSON array carrying one object per row, each
  exposing the 04-data-schema.md fields (id, category, subcategory,
  dominant_color, secondary_colors, pattern, warmth_tier, formality,
  photo_path, added_date, notes) plus a photo URL the grid can fetch

Given the catalog is empty
When a client GETs /api/items
Then it receives 200 with an empty JSON array, not an error

Given a stored photo filename
When a client GETs /api/photos/<filename>
Then the image bytes for data/photos/<filename> are returned

Given a photo request whose filename is not a plain basename inside data/photos/
  (e.g. it contains "..", a path separator, or is absolute)
When it is requested
Then the request is rejected without reading or serving any file outside
  data/photos/

Given the server is running
When its registered routes are inspected
Then only read-only catalog/photo routes exist — no create/update/delete route
```

**Agreed read-only contract for ING-020** — the sprint's chosen API shape. It is
not defined in an approved spec, so it is fixed here so the backend and frontend
tickets cannot drift:
- `GET /api/items` → `200`, JSON array. Each item:
  `{ "id": "...", "category": "...", "subcategory": "...",
  "dominant_color": "...", "secondary_colors": ["..."], "pattern": "...",
  "warmth_tier": "...", "formality": "...", "photo_path": "data/photos/<file>",
  "added_date": "YYYY-MM-DD", "notes": "" }` plus
  `"photo_url": "/api/photos/<file>"`. Empty catalog → `200 []`.
- `GET /api/photos/<file>` → the stored image bytes with the correct
  `Content-Type`; `404` when absent.

**Context / implementation notes**

- No write/edit route this sprint; a manual re-tag/re-submit route would be the
  "second writer" that `06-decisions.md` "Ingest→DB wiring" says to revisit
  later.
- The existing startup config load and warnings are unchanged.

**Out of scope:** pagination/filtering design, write/edit routes, and static
frontend serving (`go:embed` + SPA fallback is ING-021).

## Implementation notes

**Files**
- `internal/api/api.go` (new) — Gin engine + read-only handlers.
- `cmd/server/main.go` (rewritten) — `-addr` flag, Gin, opens the store.
- `go.mod` / `go.sum` — added `github.com/gin-gonic/gin v1.12.0` (plus its
  transitive deps). `go mod tidy` run; gin is a direct require.

**Exported surface added**
- `const DefaultPhotosDir = "data/photos"`
- `func New(st *store.Store, photosDir string) *gin.Engine` — builds the
  engine with only the two GET routes, so Tester can call
  `New(...).Routes()` to inspect them and drive requests with `httptest`.

**Behavior**
- `cmd/server` now parses `-addr` (default `":8080"`), loads config, opens
  `store.DefaultDBPath`, builds the engine via `api.New(st,
  api.DefaultPhotosDir)`, and serves it with
  `http.ListenAndServe(*addr, router)`. The stdlib
  `http.NewServeMux` placeholder and the hardcoded `:8080` const are gone.
- `GET /api/items` → `st.List()` mapped to the agreed contract JSON: the 11
  `04-data-schema.md` fields plus `photo_url`. `added_date` is formatted
  `YYYY-MM-DD` (`item.AddedDate.Format("2006-01-02")`). A nil/empty
  `SecondaryColors` is normalized to `[]string{}` so it emits `[]`, not
  `null`; the response slice is `make(..., 0, ...)` so an empty catalog is
  `200 []`. A `List()` error is a `500` with `{"error": ...}`, not a silent
  empty array.
- `GET /api/photos/:filename` → `validPhotoName` gate, then
  `c.File(filepath.Join(photosDir, name))`. Bytes and `Content-Type` come
  from `http.ServeFile` (extension-based); a valid-but-absent file yields
  the stdlib `404`.
- Only `gin.New()` + `gin.Recovery()` middleware; no Logger. Registered
  routes are exactly `GET /api/items` and `GET /api/photos/:filename` —
  no create/update/delete route exists.

**Traversal guard (trust boundary)**
`validPhotoName` rejects `""`, `"."`, `".."`, any `/` or `\`, and any name
containing `..`; otherwise the name is a plain basename, so
`filepath.Join(photosDir, name)` cannot escape `photosDir`. An invalid name
returns `400 Bad Request` without touching the filesystem. Percent-encoded
separators decode before routing: `%2e%2e`/`%2f` either fail the route
match or reach the guard as `..`/separators, so no traversal reaches
`c.File`.

**Assumptions / decisions for Tester + Reviewer**
1. **`New` takes a `photosDir` argument.** The ticket fixes the directory at
   `data/photos` (`07-architecture.md`), so `cmd/server` passes
   `api.DefaultPhotosDir`; the parameter exists only so tests can serve from
   a `t.TempDir()` instead of the repo's real, personal `data/photos/`.
   No path is configurable via env or CLI (that would change the approved
   contract).
2. **Listen address is the `-addr` flag**, as the ticket's Context section
   already agreed, defaulting to `:8080`. No new env var — the env contract
   in `07-architecture.md` has no listen-address variable.
3. **`photo_url` is derived from `filepath.Base(item.PhotoPath)`**, matching
   the stored `data/photos/<file>` convention, so the client receives only
   the basename. An empty `photo_path` yields an empty `photo_url` rather
   than the bogus `/api/photos/.`.
4. **Invalid photo filename → `400`, absent valid file → `404`.** The AC
   only requires that a traversal request is "rejected without reading or
   serving any file"; `400` is used so a malformed request is distinguishable
   from a missing one. Flagging the status choice since the ticket does not
   fix it.
5. **The server now opens `data/wardrobe.db` at startup**, per the ticket's
   Context ("`cmd/server/main.go` wires Gin and opens the store"). Running
   it from the repo root creates the real `data/` dir; process-level tests
   should root the binary in a temp working directory to avoid touching
   personal data. There is no DB-path override, by design.
6. No new taxonomy/schema value, no enum validation duplicated here (the
   store holds already-validated values), no write route.

  fixes `404` when absent; the stdlib `http.ServeFile` path produces it.
