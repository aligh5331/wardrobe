### [ING-019] First Gin routes: read-only catalog list + photo serving

**As a** wardrobe owner
**I want** `cmd/server` to serve a read-only JSON list of catalog items and the
stored photos over Gin, on a configurable listen address
**So that** the grid UI has an API to read from, and ING-001's standing Review
condition (real Gin, configurable address, no placeholder mux) is discharged

**Acceptance criteria** (Gherkin):
```
Given cmd/server starts with the env contract satisfied and no address override
When it listens
Then it serves through Gin (the stdlib http.NewServeMux placeholder in
  cmd/server/main.go is gone) on the default :8080

Given an address override is supplied on the command line
When cmd/server starts
Then it binds that address instead of :8080

Given catalog rows exist
When a client GETs /api/items
Then it receives 200 with a JSON array carrying one object per row, each
  exposing the 04-data-schema.md fields (id, category, subcategory,
  dominant_color, secondary_colors, pattern, warmth_tier, formality,
  photo_path, added_date, notes) plus a photo URL the grid can fetch

Given the catalog is empty
When a client GETs /api/items
Then it receives 200 with an empty JSON array, not an error

Given a stored photo filename
When a client GETs /api/photos/<filename>
Then the image bytes for data/photos/<filename> are returned

Given a photo request whose filename is not a plain basename inside data/photos/
  (e.g. it contains "..", a path separator, or is absolute)
When it is requested
Then the request is rejected without reading or serving any file outside
  data/photos/

Given the server is running
When its registered routes are inspected
Then only read-only catalog/photo routes exist — no create/update/delete route
```

**Spec reference:** `07-architecture.md` "Backend" (Gin router), "Runtime model"
(localhost), "Full project structure" (`internal/api` handlers);
`04-data-schema.md` (the fields the list exposes); `backlog/ING-001.md` "Review"
condition of approval (first route-bearing ticket must wire Gin, make the listen
address configurable, remove the empty-mux placeholder)

**Status:** Ready

**Depends on:** ING-017 (the store's `Open`/`List`). Do not start until ING-017
is Done.

**Agreed read-only contract for ING-020** — the sprint's chosen API shape. It is
not defined in an approved spec, so it is fixed here so the backend and frontend
tickets cannot drift:
- `GET /api/items` → `200`, JSON array. Each item:
  `{ "id": "...", "category": "...", "subcategory": "...",
  "dominant_color": "...", "secondary_colors": ["..."], "pattern": "...",
  "warmth_tier": "...", "formality": "...", "photo_path": "data/photos/<file>",
  "added_date": "YYYY-MM-DD", "notes": "" }` plus
  `"photo_url": "/api/photos/<file>"`. Empty catalog → `200 []`.
- `GET /api/photos/<file>` → the stored image bytes with the correct
  `Content-Type`; `404` when absent.

**Context / implementation notes**
- Handlers live in `internal/api` (`07-architecture.md` tree); `cmd/server/main.go`
  wires Gin and opens the store.
- Listen-address mechanism: a `-addr` flag defaulting to `:8080`. Chosen because
  the approved env var contract (`07-architecture.md`) has no listen-address
  variable and adding one would change a protected contract. **Flagged to Ali** —
  if an env var is preferred instead, say so before Coder starts and this AC
  changes.
- Photo serving resolves only `data/photos/<basename>`; reject any filename
  containing a path separator or `..`. This is trust-boundary validation, not
  optional.
- No write/edit route this sprint; a manual re-tag/re-submit route would be the
  "second writer" that `06-decisions.md` "Ingest→DB wiring" says to revisit
  later.
- The existing startup config load and warnings are unchanged.

**Out of scope:** pagination/filtering design, write/edit routes, and static
frontend serving (`go:embed` + SPA fallback is ING-021).
