### [ING-017] Catalog store: GORM wardrobe-item model + SQLite at data/wardrobe.db

**As a** wardrobe owner
**I want** an `internal/store` package that models the wardrobe item exactly per
`04-data-schema.md`, opens and migrates `data/wardrobe.db`, and can insert and
list catalog rows
**So that** the ingest CLI has somewhere to persist tagged items and the API has
somewhere to read them from

**Acceptance criteria** (Gherkin):
```
Given data/wardrobe.db does not exist
When the store is opened
Then data/ is created if absent, and data/wardrobe.db holds a wardrobe-items
  table whose columns cover every field in 04-data-schema.md — id, category,
  subcategory, dominant_color, secondary_colors, pattern, warmth_tier,
  formality, photo_path, added_date, notes

Given an item with a caller-supplied uuid id and all 04-data-schema.md fields
When it is inserted and then read back
Then every field round-trips unchanged, secondary_colors returns as a list of
  0 or more palette values, and added_date is the cataloging date that was
  supplied

Given several items have been inserted
When all items are listed
Then every inserted item is returned and no schema field is dropped — notes and
  secondary_colors may be empty, but neither is replaced by an unexpected value

Given the store is opened twice against the same file
When it is opened again
Then re-running the migration is a no-op and previously written rows are intact
```

**Spec reference:** `04-data-schema.md` "Data schema — wardrobe item" (field
table and "Resolved"); `07-architecture.md` "Backend" (GORM, `sqlite` driver,
`data/wardrobe.db`, `data/photos/`) and "Full project structure"
(`internal/store`); `06-decisions.md` "Ingest→DB wiring: direct call, no
provider/service abstraction yet"

**Status:** Ready

**Required exported surface** (ING-018 and ING-019 build against this; if naming
changes, both dependents must be updated in the same pass):
- `const DefaultDBPath = "data/wardrobe.db"`
- `type Item struct { ID, Category, Subcategory, DominantColor string; SecondaryColors []string; Pattern, WarmthTier, Formality, PhotoPath string; AddedDate time.Time; Notes string }`
- `func Open(path string) (*Store, error)` — creates the parent dir, opens
  SQLite, auto-migrates
- `func (*Store) Insert(item Item) error`
- `func (*Store) List() ([]Item, error)`
- `func (*Store) Close() error`

**Context / implementation notes**
- New package replacing the `internal/store/.gitkeep` placeholder; it is already
  in `07-architecture.md`'s tree.
- DB path is fixed at `data/wardrobe.db` per `07-architecture.md`. There is no
  DB-path entry in the env var contract, so do **not** add a new env var —
  callers use `DefaultDBPath`.
- `secondary_colors` is `list[enum]` in the schema and SQLite has no list type;
  store it as a JSON-encoded column (e.g. GORM `serializer:json`) and expose it
  as `[]string`. Internal storage representation only — not a schema change.
- `added_date` is the cataloging date (`04-data-schema.md` "when cataloged");
  represent it as `time.Time` (the API ticket formats it as a date).
- The store writes already-validated values. `03-taxonomy.md` enum validation is
  `05-vlm-tagging-spec.md` "Output validation", owned by the tagging pipeline
  (ING-004/ING-005); the store does not duplicate it.
- `notes` is optional and is not produced by tagging; the ingestion path supplies
  an empty value, but the store must support a non-empty future value.
- Driver: GORM with `gorm.io/driver/sqlite` (the `sqlite` driver named in
  `07-architecture.md`). If the build environment lacks CGO, a pure-Go SQLite
  driver is an acceptable substitute — document the choice in Implementation
  notes.

**Out of scope:** photo copying / `data/photos/` writes (ING-018), any HTTP
surface (ING-019), any update/delete operation (no second writer exists yet —
`06-decisions.md` "Ingest→DB wiring").

**Depends on:** nothing. First in the Sprint 2 order.
